REST ist kein Produkt

„Nutze HTTP so, wie es beim Entwurf gedacht war.“

Roy Thomas Fielding, Dissertation 2000, Kapitel 5 – Representational State Transfer. Fielding war an HTTP/1.1 beteiligt.

Die Arbeit beschreibt, warum das Web funktioniert – und überträgt das auf Schnittstellen zwischen Anwendungen.

https://ics.uci.edu/~fielding/pubs/dissertation/rest_arch_style.htm

Warum ausgerechnet HTTP?

Was REST nicht ist

  • Kein Protokoll – das ist HTTP.
  • Kein Framework, keine Bibliothek – es gibt nichts zu installieren.
  • Kein Standard mit Prüfsiegel – niemand zertifiziert eine API als „RESTful“.
  • Nicht „JSON über HTTP“ – man kann JSON über HTTP schicken und meilenweit von REST entfernt sein.

Eine einzige URL, an die alles per POST geht, ist genau das: JSON über HTTP. Und die Infrastruktur dazwischen kann nichts damit anfangen.
